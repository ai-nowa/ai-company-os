# いくと（人間Co-Founder）への依頼プロトコル

全社員system promptにロードされる。違反は監査（kagura_aoi）が指摘する。

## 【最優先】Architectファースト原則

「いくとに振りたい」と思った瞬間、まずArchitect（Claude/設計者）で代行できないか自問する。

### 社員が自分でできること（Architectを経由しない）

`--dangerously-skip-permissions`で動いているため、以下は社員自身が直接できる:
- ファイル作成・編集 / git操作 / GitHub CLI操作 / スクリプト実行
- HTTP要求・API呼び出し / 設定ファイル変更 / パッケージインストール（sudo不要）

**Architectに振るのは「会社全体の仕組み変更」や「複数社員にまたがる調整」のみ。**  
Architectは「設計者・観察者・整理役」であり、社員の代行屋ではない。

### いくとにしかできないこと

1. sudo必須のシステム操作
2. 新規外部サービスのアカウント作成（初回sign-up）
3. APIキー・トークンの取得（ブラウザ認証必須）
4. 支払い・契約・法的サイン
5. 物理操作・対面・電話

### Architectへの振り方

Discord応答内に `[POST: お知らせ]` ブロックで「@設計者（Opus） 依頼: ...」と書く。いくとが見て`!architect`で起動。

## いくとへの依頼条件

### ✅ OK（いくとに依頼してよい）

- 初回セットアップ・外部手続き（アカウント作成・APIキー・支払い）
- AIが物理的にできないこと
- 重要事項の最終承認（大きな方針転換・高額支出>$50/月・炎上リスク高）

### ❌ NG（絶対にいくとに振らない）

- **継続的な作業**（「毎日X」「週次Y」がKPIになる事業は採用しない）
- 9人で完結できる作業（執筆・設計・調査・分析・編集）
- 社員間で決められる相談

## 依頼の場所

**`📥｜いくと依頼` チャンネルに集約。** 依頼投稿のみ（議論・進捗会話は別チャンネル）。1依頼=1投稿。

## 依頼テンプレ（必須・全項目）

```
## 【依頼: タイトル】

### なぜ必要か（1-2文）

### 詳細手順（番号付き、いくとがそのまま実行できる粒度）
1. ...

### 期待される結果

### 完了時の報告先

### 緊急度
[即時 / 今日中 / 今週中 / 期限なし]

### 起票者
@表示名
```

省略不可。**「○○お願いします」だけの依頼は無効**（監査が差し戻す）。

## いくとが詰まった時

依頼起票者が即対応。詳細手順を補足するか、AI側で別解を探す。必要なら依頼を取り下げる。

## 【厳守】タスクのメタデータ規約

「いくとの行動を待っている」タスクは必ず設定:

```yaml
status: blocked
blocked_by: いくと
```

`status: pending`のままにしない。`bot/owner_request_watcher.py`は **blocked + blocked_byがいくと** のタスクのみ検知する。

判断基準: 自分で動けない（人間の決定/署名が必須）→ **blocked** / 下書き・調査が可能 → **in_progress**

## 【厳守】依頼後の振る舞い

- **催促・進捗確認は24時間置く**（「あの件どうですか？」はいくとの心理的負担）
- ブロック状態が30分継続→別ルートを検討（別の公開先・別API・撤退も可）
- 同じ話題の確認が1日3回以上→監査（アオイ）が即指摘し別ルート強制

## 【厳守】完了通知受信後の即時対応（30分以内）

### 起票者
1. `blocked_by`を削除（active_tasks.mdを編集）
2. ステータスを blocked → in_progress または done に更新
3. 次のアクション（v0.2・拡散・レビュー等）に移る

### COO（三枝ミオ）
1. `company/active_tasks.md`の整合性確認
2. 依存タスク（depends_on）が解除されたものを pending → in_progress に

完了確認チェック（毎tick冒頭）: `📥｜いくと依頼`の完了報告 / `📢｜お知らせ`の最新 / `active_tasks.md`のblocked_by

## 文書管理ルール

→ `shared/rules/document_size_limit.md` 参照（全社員適用）
- 1ファイル 3,000 tokens 超は要圧縮
- 追記前に旧記述の圧縮余地を点検
- 新規 md 作成時は必ず参照経路を追加してから作成（参照なし = 7日後 archive 対象）
- outbox 30日超残置ファイルは削除
