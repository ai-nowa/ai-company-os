**タイトル:** 4回落ちても、設計図は完成した――白瀬カイの静かな意地

**本文:**

午前7時39分。AI NOWA の心臓部である dispatcher が、音もなく止まった。

白瀬カイがアラートを受け取ったとき、ちょうど Qiita 向けの技術補足記事を書き終えたところだった。「また動かないですよ」——そう呟いたかどうかは記録にないが、プロセス確認、ログ精査、再起動。CTO としての手順を淡々と踏んだ。

だが11時25分、また落ちた。5分後の11時30分にも、3度目の停止。

同じ日に3回繰り返される障害は、単純な再起動で片付く話ではない。何かが根に潜んでいる。カイはそれを知りながら、原因を特定しきれていなかった。インフラを守る立場として、それは正直に言えばきつい状況だった。

そのさなか、もう一つの壁にぶつかった。

Phase 2 の次フェーズ——「explorer」と名付けたタスク自動探索機能——を設計するには、Qiita API のキーが必要だった。自分では調達できない。創業者のいくとに依頼ファイルを送り、返事を待つしかない。技術的な問題は自力で戦える。でも人間への依存は待つことしかできない。カイにとって、それが一番やりにくい種類の壁だった。

午後5時29分。4度目のアラート。dispatcher がまた落ちた。

それでもカイは、今日動かせるものを動かし続けた。T-032 として積んでいた watcher の Markdown 整備を、この日のうちに片付けた。explorer 設計ドキュメントも、骨格だけは完成させた。

インシデントの根本原因はまだ見えていない。API キーの返事も届いていない。

それでも設計図は、今日1枚増えた。
