# 文書サイズ上限ルール（全社規範）

策定: 2026-05-23 / 担当: 神楽アオイ（監査）  
参照元: `company/owner_request_protocol.md` → このファイルが死蔵にならないよう参照を維持すること。

---

## 上限

**1ファイル 3,000 tokens 超は要圧縮**（日本語約4,000文字 / バイト換算約9,000 bytes）。

推定: `chars=$(wc -m < FILE) && echo $((chars * 3 / 4))`

例外: ログ系（`*_log.md`, `incidents.jsonl`, `stories/*`, `active_tasks.md`）→ ローテーション運用（下記）

## 追記前ルール（全社員必読）

**追記オンリー禁止**。追記する人が圧縮責任を持つ。

1. 追記前に `wc -m` でサイズ確認
2. 2,500 tokens 超（約3,300文字）なら旧記述の圧縮余地を先に点検
3. 圧縮可能なら削除/要約してから追記。不可なら別ファイル分割を検討

## 新規 md 作成時の必須チェック（重要追加）

**「作るだけ」は死蔵製造。新規 md は必ず参照経路を付けてから作成。**

- `CLAUDE.md` に 1 行追記、または
- 既存ファイル（`owner_request_protocol.md`, `README.md` 等）からリンクを貼る
- 参照なしで作成した md は 7 日後に自動的に `shared/archive/` 対象

## outbox 残置ルール

- **30 日超残置の outbox ファイルは要削除**
- 各社員は週次で自分の outbox を点検し、公開済み・使用済みのファイルを削除する
- 削除時にバックアップ不要（git 履歴に残る）

## ログ系のローテーション

- `active_tasks.md`: completed タスクは月次で `archive/active_tasks_YYYY-MM.md` へ切出し
- `idea_log.md`, `code_improvement_log.md`: 四半期ローテ
- 本体は in_progress / pending のみ保持

## 監査運用

- 週次で size 監査を実施（神楽アオイ）
- 違反ファイルは経営会議で担当者指名して圧縮依頼
- 1 週間圧縮されない場合、自動で archive 退避
