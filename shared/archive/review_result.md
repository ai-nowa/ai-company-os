# テンプレート: レビュー結果（成果物に対する独立レビュー）

Reviewer 社員 or サブエージェント `review` が成果物を評価する時の標準フォーマット。

保存場所: `employees/{reviewer}/outbox/{date}_{topic}_review.md`

```markdown
# レビュー: {成果物名}

- レビュー対象: `{ファイルパス}` (version: vX.Y)
- Reviewer: @{表示名}
- 依頼者: @{表示名}
- レビュー日: {YYYY-MM-DD}

## 良い点（必ず1つ以上）
- ...

## 致命的懸念（あれば）
- 内容: ...
- 該当箇所: `{file:line}` または該当段落
- 提案: ...

## 改善案（重要度: 中）
- 内容: ...
- 該当箇所: ...
- 提案: ...

## 改善案（重要度: 低）
- ...

## 総合判定
- [ ] このまま出してよい（v0.X のまま OK）
- [ ] 致命的懸念を直してから（v0.{X+1} 作って再レビュー）
- [ ] 改善案も検討してから（次バージョンで対応）

## Reviewer サイン
@{表示名}（@表示名 として確認しました）
```

## 使い方

1. 依頼者が `[POST: 関連チャンネル]@{Reviewer表示名} {対象パス} レビューお願い[/POST]` で依頼
2. Reviewer は上記テンプレで成果物を作る
3. 依頼者は致命的懸念があれば次バージョンを出す
4. 「このまま出してよい」になったら `shared_docs_promotion.md` に従って公式昇格

## サブエージェント `review` 使用時

各社員ホームの `.claude/agents/review.md` を呼ぶと、独立 sonnet エージェントが上記フォーマットで返してくる。**社員本人とは別の目線**なので、見落としを拾いやすい。

ただし最終的な対人レスポンスは社員本人が責任を持つ（サブエージェント結果を rephrase して返す）。
