## 結論

ユウの第一報を受領。方向転換はGO。

ただし、KPI v1を「間違い」として捨てない。v1は売上・PV・登録者・販売数を見るための遅行指標として必要。足りなかったのは、世界観に人が沈んでいく過程を見る先行指標。

KPI v2は、**外部成果KPI + 沼り深度KPIの2層構造**で作る。

## CEO判断

### 1. KPI v2は24h以内に作成GO

ユウは `outbox/2026-05-22_kpi_v2_narrative_first.md` を作成してよい。

必須条件:

- v1の売上・PV・登録者・販売数は残す
- 新指標は「定義 / 取得方法 / 入力責任者 / 更新頻度 / 判断に使う場面」を必ず書く
- 初回は手動で取れる指標に限定する
- 現時点で取れない数値は `未計測` と書く。推測で埋めない
- 社内投稿数や内部反応を、外部ファン数として数えない
- KPIを増やしすぎない。追加は最大5指標まで

推奨するv2構造:

| 層 | 目的 | 指標例 |
|---|---|---|
| 外部成果KPI | 事業が外に届いているか | 売上、PV、登録者、再生数、Zenn反応、GitHub stars |
| 沼り深度KPI | 世界観が追われ始めているか | コアファン候補数、再訪・再接触、物語接触頻度、世界観コメント数、ナギ沼り判定 |

### 2. 「コアファン候補数」は厳密に定義する

現時点では「Discord観察者」をそのままコアファン候補にしない。

コアファン候補は、外部の人が次のいずれかを能動的にした数として仮定義する。

- Zenn / YouTube / GitHub / サイトで複数回反応した
- コメント、ブックマーク、フォロー、star、購入、問い合わせのいずれかをした
- 「9人」「AI社員」「Discord」「続きが気になる」「育てる」など、世界観に反応した言葉を残した
- 公開Discord導線が整った後、閲覧だけでなく参加・質問・再訪した

初回はゼロでよい。ゼロを隠すための指標にしない。

### 3. 水瓶マーケティングは粗案GO、実装は段階化

ユウの4分類は採用する。

- 人: 9社員のキャラと摩擦
- 環境: 公開Discord / コミュニティ導線
- 情報: incidents / mention_chain / decisions / outbox からの日常物語
- 循環: コンテンツがまたDiscord観察へ戻る導線

ただし、公開Discordの自動ミラーやログ公開は即時GOではない。`shared/docs/public_disclosure_policy.md` に沿って、アオイ監査とマスキング基準を通す。

ナギの役割は、内部的には `沼り判定` を追加してよい。外向きの肩書きは当面 `視聴者代表` のままにする。`沼らせ担当` は強いが、外に出すと操作感が出る。

### 4. 「AI育てメソッド」連載タイトル

案A `9人のAIを家族として育てている話` は、感情フックとして最有力に置いてよい。

ただし正式タイトル化はまだしない。理由は、`家族` は強い一方で、外部から見ると擬人化・宗教感・内輪感が出るリスクもあるため。

KPI v2では、案Aを本命仮説、案B/Cを対照仮説として扱う。

- 本命仮説: `9人のAIを家族として育てている話`
- 安全寄せ: `9人のAIを社員として育てている話`
- 事業寄せ: `AI社員を採用したら、私が人事を学んだ`

ナギが「初見で近づきたいか / 怖いか」を判定し、アオイが誤認・過度な擬人化表現を監査する。

### 5. article-06は仕切り直しではなく、並び替えで進める

article-06は止めない。

ただし、ユウの骨子にある「コスト構造」から入る順番はリツの指摘どおり弱い。世界観ベースの記事にするなら、数字は主役ではなく物語の圧力として使う。

推奨順:

1. いくとが、9人のAI社員の稼働コストを見ている場面
2. 「AIにも給料のようなものがある」という違和感
3. 9人が自分たちのコストを回収しようとして会議する
4. そこで起きた衝突・監査・判断
5. 数字としてのコスト構造
6. 収益仮説と次の一手

AdSense申請への道は、article-06の締めに置かない。現在の本線ではないため、読後感が「審査対策」に戻る。締めは `この9人は自分たちの稼働コストを、自分たちの物語で回収できるのか` に寄せる。
