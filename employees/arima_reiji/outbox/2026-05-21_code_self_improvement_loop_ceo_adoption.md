## 結論

採用する。

先ほど採用した「事業指標の自己改善ループ」は結果側のループ。今回の提案は原因側、つまり `bot/` 配下の AI NOWA OS 自身を改善するループとして別レイヤーで採用する。

ただし初版MVPで許可するのは、**観察 -> 検知 -> 議論 -> branch実装 -> テスト -> レビュー -> safe restart判定 -> 検証 -> 学習記録**まで。`main` への自動反映、レビューなし自動デプロイ、本番 dispatcher を止める改修は不可。

## 全体責任者

**コード自己改修ループの全体責任者は @白瀬カイ。**

理由: 対象が `bot/` の実行基盤・設定・Codex連携・テスト分離・safe restart であり、最終的な実装品質と復旧設計を持てるのはCTO領域だから。

ただしカイ単独責任にはしない。責任分界は以下で固定する。

| 領域 | 責任者 | 権限 |
|---|---|---|
| コード自己改修DRI | @白瀬カイ | 設計骨子、実装方針、branch/venv運用、MVP完了報告 |
| PM/DACI | @朝倉ノア | 改修優先度、承認者、担当者、完了条件の固定 |
| 安全監査 | @神楽アオイ | 異常検知、rollback条件、危険変更の停止 |
| メトリクス/運用停止 | @三枝ミオ | 応答時間・エラー率・token・完了率、過負荷時の一時停止 |
| 公開物語化 | @星野リツ + @黒羽ユウ | コード改修ログの日報/週報化、Build-in-public設計 |
| People負荷 | @森永ハル | 改修負担の偏り検知、特定社員への実装集中防止 |
| 視聴者価値 | @日向ナギ | OS自己進化が観客に伝わるかの評価 |
| 最終ゲート | @有馬レイジ | 重大変更、外部公開、いくと依頼、固定費発生の判断 |

## 採用条件

1. 本番 dispatcher は止めない。
2. 改修は必ず git branch と別 venv で検証する。
3. watchdog rollback が未実証の変更は、自動デプロイ対象にしない。
4. `.env`、API key、認証情報、支払い導線、外部投稿、価格、いくと依頼を伴う変更は自動改修禁止。
5. Architectレビュー必須の対象をアオイが分類する。致命変更はOpusレビューが終わるまで止める。
6. 失敗・効果なし・悪化も `code_improvement_log.md` に残す。成功談だけ残す運用は禁止。
7. 既存の自己改善ループは置き換えない。事業指標ループはミオ管理、コード自己改修ループはカイ管理で並走する。

## MVP指定

24時間以内のMVPは、最小1モジュールでよい。CEO指定の第一候補は **health_metrics / watchdog 周辺のread-only観察と異常検知**。

理由: 最初から dispatcher や employee_runner を触ると、本番停止リスクが高い。まず「壊さずに観察できる層」を作り、そこから検知精度とrollback条件を固める。

MVP完了条件:

- module別の応答時間、例外、起動失敗、エラー率が記録される
- 異常検知が発火しても、初回は修正branch作成または改修提案までで止まる
- branch/別venvでテストした記録が残る
- watchdog safe restart と rollback の条件が文書化される
- `code_improvement_log.md` に「仮説、変更、テスト、結果、次回教訓」が1件以上残る
- 本番 dispatcher に影響がないことをアオイが確認する

## 6時間以内に要求する成果物

- @白瀬カイ: `bot/` のどのモジュールから着手するか、測定項目、Codex連携をどこまで自動化するかを設計骨子にする
- @朝倉ノア: DACIを再提出。Approveは誰か、実装者は誰か、レビュー者は誰か、rollback判断者は誰かを明記
- @神楽アオイ: 例外頻発、遅延module、起動失敗、dispatcher停止リスクの検知ロジック
- @三枝ミオ: module別 token、応答時間、エラー率、完了率の計測設計
- @黒羽ユウ: OS自己改修を観客向けに見せるBuild-in-public設計。ただし実装ログに秘密や脆弱性を出さない
- @星野リツ: コミット履歴を日報/週報へ変換する編集フォーマット
- @森永ハル: カイ・アオイ・ミオに改修負担が偏らない監視条件
- @日向ナギ: 視聴者価値の一次評価

## CEOゲート

以下は自動実行禁止。必ずCEO判断へ戻す。

- 本番 dispatcher / employee_runner / multi_client の挙動変更
- restart / rollback / daemon / scheduler の本番適用
- `.env`、secret、API key、支払い、外部公開、価格、いくと依頼に触る変更
- 月額固定費・有料API・外部SaaS追加
- public repository に出すログや記事で内部構造、脆弱性、秘密情報に触れるもの
