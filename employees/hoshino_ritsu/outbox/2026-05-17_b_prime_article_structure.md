## 全体構成

### リード（無料・約400字）

シーン: dispatcher が雪だるま式に並列プロセスを吐き、強制 kill を強いられた瞬間。
→ 「AI社員9人が並列に動く会社を、3週間で作って崩壊させかけた」
→ 「これは設計記録ではなく、**踏んだ罠の一次資料**です」

---

### Chapter 1. なぜ崩壊しかけたか（約600字）

- AI NOWA の構造（9社員 / Discord / 自律ループ）を3行で
- 「動かす」を優先した結果、複数 dispatcher 暴走 → 強制 kill 複数回
- 本記事の読み方: **罠11個を順に開示する。各罠は実装で踏んだ実話**

---

### Chapter 2. 11個の設計トラップ（約3,000字 / 主役パート）

各罠を以下フォーマットで統一:

```
## 罠 #N: {タイトル}

**症状**: {何が起きたか}
**実記録**: > {learnings_design_traps.md からの引用}
**解**: {採った対策}
```

掲載順（learnings ファイル準拠 #1〜#11）:

| # | タイトル | 重要度 |
|---|---------|-------|
| 1 | visited セットの持ち越しで A→B→A が不可能 | 中 |
| 2 | 連鎖2系統発火で雪だるま暴走 | **高（崩壊根拠）** |
| 3 | CLI `--add-dir` 貪欲解析が prompt を吸収 | 中 |
| 4 | 「Claude Code として動く」プロンプトが社員人格を上書き | 中 |
| 5 | ランダム間隔は社員の業務リズムを表現できない | 低 |
| 6 | 応答=Discord 投稿固定で自由度消失 | 中 |
| 7 | 「業務時間」概念で AI が終わりモードに入る | 中 |
| 8 | キュー処理完了後 unlink で重複起動 | **高（崩壊根拠）** |
| 9 | 同期 await でキュー全体ブロック | **高（崩壊根拠）** |
| 10 | 完了通知後の即時更新責任が未明文化 | 低 |
| 11 | 設定とコード分離不在で再起動頻発 | 中 |

→ 高重要度3件（#2/#8/#9）は実記録引用を**2〜3行に拡張**してドラマ密度を担保。
→ それ以外は1〜2行で簡潔に。**ただし11個すべて省略しない**。

### Chapter 3. 罠から抽出した3つの設計原則（約800字）

2. **「人間概念を AI に持ち込むな」**（罠#4/#7から）
3. **「設定はコードから外せ」**（罠#11から）

→ 罠の羅列で終わらせず「次に作る人」に渡せる形に。
