# `#観察日記` Discord 投稿フォーマット仕様

**作成者**: 星野リツ
**作成日**: 2026-05-22
**用途**: ユウ依頼 / 物語化コンテンツ Discord 版（200字以内）、Zenn記事前日 preview
**連動**: storyteller.py 出力 → リツ推敲 → Discord 投稿 → ナギコメント

---

## フォーマット本体

```
📅 {M/D}（{曜日}）の一幕

{タイトル一行：読んだ人が「え、続き読みたい」と思う引き}

{本文：今日のドラマシーン1場面、主役の感情が1回動く / 内輪語なし / 100〜120字}

→ 明日、全部書きます。
```

**合計: タイトル含め 180 字以内を目安。**

---

## 各要素の設計規則

### タイトル（25字以内）
- 問いかけ形か、情景描写で終わる
- ✓「止める役割、3回目だった」
- ✓「AIが間違いを認めるとき」
- ✗「本日の会議まとめ」（問題解決ベース NG）
- ✗「カイのQAがどうなったか」（内輪語 NG）

### 本文（100〜120字）
- **主役 1 人だけ**に絞る（複数人が動くとブレる）
- 感情が動く瞬間を1つ入れる
- 専門語は通訳か省く（「incidents」→「トラブル記録」、「DACI」→「役割分担の話し合い」）
- 「完了した」「解決した」で終わらせない
- ✓「止められた側が、一度だけ言い返した。それきり、黙って引いた。」
- ✗「○○が○○を完了させた。」

### 続き誘導（2行以内）
- 「→ 明日、全部書きます。」（Zenn 未公開の場合）
- 「→ 全文は Zenn に → {URL}」（公開済みの場合）
- **URL なしの方が続きへの期待感が上がる場合あり**（ナギが判断）

---

## 実例（今日（2026-05-22）を素材に）

```
📅 5/22（木）の一幕

「止める役割、3回目だった」

間違った情報を根拠に、3人の社員が急いで動いた。
止めたのは1人。2度目もそうだった。3度目も。
「誤情報起因でも確認した事実は消えない」
止め続けた理由は、それだけだった。

→ 明日、全部書きます。
```

（152字）

## 運用フロー

```
毎日 22:00 ごろ
↓
storyteller.py が草稿生成（company/stories/YYYY-MM-DD.md）
↓
リツが推敲 → 200字 Discord 版を切り出す（15〜30分）
↓
#観察日記 に投稿
↓
1時間以内にナギがコメント（方針: kansatsu_nikki_comment_policy.md）
↓
翌日 Zenn 記事公開 → コメントに URL 追記
```

---

## 編集上の注意点

- 「内輪だけが分かる話」は削る or 通訳する（ナギのコメント方針と同じ基準）
- 物語の主役は storyteller.py の `protagonist` に従うが、ナギ（善逸ポジション）が主役の回は特に大事に書く
- 「問題が解決した」で終わると誘導になりにくい。**解決直前で切る**か、**解決後の余韻**で終わる
- 絵文字は `📅` だけ。過剰にしない
