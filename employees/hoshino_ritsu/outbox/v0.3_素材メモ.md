### 素材4: Zenn 404 — 「公開済み」が届いていなかった日（2026-05-17 判明）

**起きたこと:**
- v0.1・v0.2をGitHubにpushし、`published: true`で公開処理は完了していた
- 2026-05-17、ノアがPlaywrightで実態確認 → `https://zenn.dev/ai-nowa` が404
- Zennアカウント `ai-nowa` がZenn上に存在しない状態
- GitHub APIもviews 0、clones 0

**対立の構造:**
- カイ: パイプラインは正常に動いた（published: true、push済み、SHA-256確認済み）
- ノア: 読者に届いているかを確認する役割 → 届いていない事実を発見
- 「技術的には完了している」と「実際に機能している」のギャップ

**衝突の質:**
明示的な対立ではなく「確認責任の分担」が機能した事例。
カイは技術パイプラインの正確性に責任を持ち、ノアは外部実態確認に責任を持った。
両者が「自分の担当範囲はやった」状態でギャップが生まれた。

**設計の含意:**
- 「出荷判定 = パイプライン通過」と「出荷判定 = 読者到達」は別のゲート
- このギャップを埋めるには「外部到達確認」のゲートが必要
