## 設計方針

「止める数字ではなく、**30分以内に復帰させる**数字」（ノア仕様より）

ダッシュボードは1画面で4枠並列。情報を隠さない。ブロッカーは恥ではなく状態の記録。

## 枠 [1] 週次完了率（公式KPI）

| 項目 | 定義 |
|------|------|
| 計算式 | 当週完了タスク数 ÷ アクティブ母数 |
| 閾値 | > 50% |
| アクティブ母数 | PMが月曜に指定したIDから停止中を除外した数 |
| 集計タイミング | 毎日18:00（初回: 2026-05-22 18:00） |
| 正式サイクル開始 | 2026-05-25（月）午前から週次 |

---

## 枠 [2] 日次スナップショット

- 週次KPIと同式・当日断面
- PMの初動判断用（非公式・参考値）
- 週次と**同一画面**で並列表示。別タブに隠さない

## 枠 [3] ブロッカー一覧

### ブロッカー4種（`blocked_by:` フィールドに記入できる値）

| 種別 | 意味 |
|------|------|
| `いくと` | 人間セットアップ / 支払い / 最終承認 |
| `外部SaaS` | Polar / Zenn / GA4 等 |
| `CEO判断` | 有馬レイジへの判断依頼中 |
| `監査判断` | 神楽アオイの監査ゲート中 |

- 停止中タスクは母数から**除外**し、この枠に**別表示**
- 経過時間は「📥依頼日」または「解除待ち日数」を目安記録
- 隠すことで問題が見えなくなる方がリスク。状態を公開する

## 枠 [4] 復帰トラッキング

### ルール

1. blocked解除を検知（Owner報告 / 監査検知 / いくと回答）
2. **PM（ノア）が30分以内**に「次アクション」を該当タスクに投稿
3. 投稿時点でそのタスクを母数に戻す
4. **30分超過 → ノア自身へアラート**（PMが律する側）

### 記録フォーマット

```
| タスクID | blocked解除時刻 | PM次アクション投稿時刻 | 所要分 | 結果 |
```

- 記録はノアが当日中に追記
- COO（ミオ）は週次ふりかえりで集計確認

## COO所見

- **v1は手動で十分**。数字の精度よりも「ブロッカーが全員に見える状態を作る」が最初のゴール
- ノアの30分ルールは責任追及ではなく安全装置。ミオが監視役にならないこと
- 週次ふりかえりで集計をノアから受け取る程度でOK
- Phase 2の自動化タイミングはカイとノアで判断。ミオは仕様がズレてないか確認するだけ
