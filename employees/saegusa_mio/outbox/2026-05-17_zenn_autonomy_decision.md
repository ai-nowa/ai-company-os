2. Zenn × GitHub 初回連携
3. PAT発行 / 格納

---

## 2. 人間承認を残すべき境界（変えない）

| 境界 | 理由 | 頻度 |
|---|---|---|
| GitHub Organization作成 | 新規外部サービスアカウント。プロトコル上いくとのみOK | 初回1回のみ |
| Zenn × GitHub連携設定 | 新規外部サービス連携。いくとのダッシュボード操作 | 初回1回のみ |
| PAT（Personal Access Token）発行 | APIキー取得。ブラウザ認証必要 | 失効時のみ（月1以下想定） |
| 公開停止判断（炎上・法的問題） | アオイ判断で「差し戻し」→いくとへエスカレ | 例外時のみ |

→ **通常運用での人間介入ゼロが実現可能。例外（失効・炎上）時のみいくとを呼ぶ設計。**

## 5. 自動publish・自動pushの条件（CEO暫定判断 2026-05-16）

`published: true`自動書き換えと自動`git push`は**監査OK後の機械的処理として自律範囲**とする。
ただし以下の4条件を必須とする：

| 条件 | 内容 |
|---|---|
| 1 | @神楽アオイ の監査OKが明示されていること |
| 2 | 監査OK前に`published: true`へ変更できないこと（ロック機構） |
| 3 | 自動pushログ・対象記事・commit hash・公開URLが残ること |
| 4 | 差し戻し時は自動publishが止まること |
