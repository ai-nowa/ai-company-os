---

## 評価軸の構造

読者価値を3層で測る。

```
Layer 1: 到達（読んだか）
Layer 2: 共鳴（刺さったか）
Layer 3: 行動（動いたか）
```

---

## Layer 1: 到達（読んだか）

| 指標 | 取得方法 | いくと依存度 | 自動化可否 |
|------|---------|------------|---------|
| Zennページビュー | Zenn統計ページ（週次自動集計あり） | 🟢 不要 | 🟡 手動確認（Playwright等で自動化候補） |
| GitHubリポジトリクローン数 | GitHub API: `/repos/{owner}/{repo}/traffic/clones` | 🟢 不要（PAT認証） | 🟢 自動取得可 |
| GitHubユニーク訪問数 | GitHub API: `/repos/{owner}/{repo}/traffic/views` | 🟢 不要 | 🟢 自動取得可 |

**最小確認頻度**: 週1回（手動確認で十分）

---

## Layer 2: 共鳴（刺さったか）

| 指標 | 取得方法 | いくと依存度 | 自動化可否 |
|------|---------|------------|---------|
| Zennいいね数 | Zenn記事ページ / API | 🟢 不要 | 🟢 自動取得候補 |
| Zennブックマーク数 | Zenn記事ページ | 🟢 不要 | 🟡 手動確認 |
| GitHubスター数 | GitHub API | 🟢 不要 | 🟢 自動取得可 |
| Zennコメント | Zenn記事ページ | 🟢 不要 | 🟡 手動確認 |

**判定基準（v0）**:
- いいね10以上 = 刺さってる
- ブックマーク率（ブックマーク/いいね）50%以上 = 「後で使う」意図あり
- スター1以上 = リポジトリに価値を感じてる

---

## Layer 3: 行動（動いたか）

| 指標 | 取得方法 | いくと依存度 | 自動化可否 |
|------|---------|------------|---------|
| GitHubフォーク数 | GitHub API | 🟢 不要 | 🟢 自動取得可 |
| Discord相談チャンネル着信数 | Discordログ（bot管理） | 🟢 不要 | 🟢 自動カウント可 |
| 相談からの設計着手数 | ミオが経営会議で記録 | 🟢 不要（AI社員）| 🟢 ログベース |

**Layer 3の価値**: 「読んだだけ」から「動いた」への転換率が収益化の鍵
