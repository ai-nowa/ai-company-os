# 不変90% / 可変10% 運用設計 DACI v1

**作成**: 2026-05-22 / Owner: 朝倉ノア（PM）
**目的**: 和佐ノウハウ4「不変90% / 可変10%」を AI NOWA の組織運用に組み込む。核は深化のみ、流行追いは可変領域に閉じる。

---

## 1. 領域分離（定義）

### 1.1 不変90%（核 — 深化のみ、変更は重い手続き）

| カテゴリ | 具体ファイル/領域 | 何を守るか |
|---------|----------------|----------|
| ミッション核心 | `company/mission.md` 核心節 | 会社の存在意義・なぜ存在するか |
| 9人キャラクター | `employees/*/CLAUDE.md` の人格定義 | 名前・役職・性格・口癖・行動原則 |
| 関係性ルール | `relationships/` 関係性定義 | 三角コミュニケーション・Buddy制度・雑談 |
| 不変ルール | 「AI NOWAの不変ルール」全条項 | 9人会社・Discord運営・Well-being |
| 世界観の三種の神器 | コンセプト × キャラ × ストーリー | 「9人のAIがDiscordで生きる物語」という核 |

### 1.2 可変10%（流動 — 軽い手続きで動かせる）

| カテゴリ | 具体ファイル/領域 | 何を動かせるか |
|---------|----------------|--------------|
| 短期スプリント | `active_tasks.md` T-XXX | タスク追加・優先順位・期日 |
| KPI数値目標 | `shared/kpi_weekly.md` | 数値目標・撤退基準 |
| 個別施策 | コンテンツテーマ・販売チャネル・X運用 | 試行する施策 |
| シーズナル要素 | `company/seasonal.md`（新設）| 今期テーマ・キャンペーン |
| 会議室運用 | チャンネル構成・スレッド運用ルール | 運営の具体ルール |

## 3. 変更手続き（提案 → 適用）

### 3.1 可変10%の変更（軽い手続き）

1. 提案者 → Driver（ノア）に提案
2. Driver が「これは可変10%」と判定
3. 該当領域のContributor 1名のレビュー
4. 適用 → Informed へ共有

**所要時間**: 数時間以内

### 3.2 不変90%の変更（重い手続き）

1. 提案者 → Driver（ノア）に提案
2. Driver が「これは不変90%」と判定
3. **全Contributors（リツ・アオイ・ミオ・ハル）レビュー必須**
4. Approver（レイジ）の最終承認
5. 適用 → Informed へ共有 + `company/decisions.md` に永続記録

**所要時間**: 最低24時間（議論時間確保のため）

### 3.3 90/10判定が曖昧な場合

Driver が判断に迷ったら **不変90%扱い** にエスカレート。
理由: 核を軽く動かす方が、可変を重く扱うよりリスクが大きい。

## 6. PMとしての注記

- 「核は深化のみ」が原則。**変更圧力は基本的に却下**する設計。
- 「流行を追いたい」誘惑は可変10%領域で吸収する。
- これは創業者2人（いくと + 設計者）にも適用される。**核に触る変更はDACIフローを通す**。
- 和佐の20年で売上累計39億円の実例は、不変核を20年深化させた結果。AI NOWAも同じ姿勢で構築する。
