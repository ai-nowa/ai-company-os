## 前提：各段階の完了条件の定義方法

**PM観点の完了条件 = 「市場・観察者目線で何が変わるか」を明示する**

技術的に動く ≠ 完了。外から見たときに「何かが変わった」が確認できること。

---

## 段階 1: 最小スコープ（L2 ホットリロード）

**スコープ**: autonomy / 社員プロンプト のみ。L1（Discord通信）は触らない。

**技術完了条件（カイ定義予定）**:
- 対象社員が自分のプロンプト/autonomy設定を変更
- dispatcher 再起動なしで次の会話から反映される

**市場・観察者目線の完了条件**:
- Discord上で「ノアがプロンプトを変えた → 次の発言から変化が見える」がリアルタイムで起きる
- = 「AIが自分自身を学習する様子を公開で見せられる」コンテンツ素材になる

**撤退基準（レイジ判断待ち）**:
- TBD

**次段階への移行トリガー**:
- 全9社員が段階1の変更を1回以上実行できたこと

---

## 段階 2: テストハーネス + ロールバック

**スコープ**: 変更前 smoke test、失敗時の自動 git revert + 再起動

**技術完了条件（カイ定義予定）**:
- commit → test → pass なら deploy / fail なら auto-revert
- 失敗履歴がダッシュボードで見える

**市場・観察者目線の完了条件**:
- 「AIが間違いを自動検出して自分を直す」が観測できる
- 失敗→回復のサイクルがDiscordに流れる = 素人性・摩擦の保護（和佐原則10）
- ゴミ屋敷状態が「整理される様子」として価値になるのと同じ構造

**次段階への移行トリガー**:
- ロールバックが1回以上本番で機能したこと（テストではなく本番で）

---

## 段階 3: 完全自動化（commit → auto-deploy）

**スコープ**: 社員が自分の領域に commit → CI通過 → 自動 deploy。いくと介入ゼロ。

**技術完了条件（カイ定義予定）**:
- L1変更: 短時間断（10秒以内）デプロイ自動化
- L2変更: ホットリロードのみで完結
- 権限制御: 社員=自分領域のみ、Architect=拒否権

**市場・観察者目線の完了条件**:
- **いくとが「何もしなかった1週間」が実現する**
- これをそのままコンテンツ化できる：「AIだけで1週間自己進化した記録」
- = AI会社のコンセプト証明 = 最大のストレート（和佐原則13）

**これが完成したとき何が変わるか（最重要）**:
- 「AIで楽して稼ぐ」と見えるのではなく「AIが自分で育つ会社」が実証される
- 観察者が増える理由：「失敗しながら自己修正するAI会社」は世界でここだけ
- これ自体が唯一無二の世界観コンテンツになる
