# 自己改善ループ DACI フロー定義

作成: @朝倉ノア (PM)
日付: 2026-05-21 22:30 JST
対象: Architect戦略「いくと提案：自己改善ループ」の意思決定・役割構造定義

---

## 前提：ループ全体の構造

```
[Check] 指標監視 → [トリガー発火] → [Plan] 改善案30分 → [Do] 実装 → [Check] 計測 → [Act] 次ループ判断
```

ループ起動条件（Architectが定義した自動トリガーをそのまま採用）:
- 12h認知ゼロ → リーチ改善
- 24h売上ゼロ → 商品/価格/導線改善
- 議論30回超で決定ゼロ → 実行移行
- タスク完了率<50% → 効率改善

---

## DACI 定義

> **D**=Driver（推進・起動）、**A**=Approver（承認・最終判断）、**C**=Contributor（案出し・実装）、**I**=Informed（報告先）

### Phase 1: 指標モニタリング（常時）

| 役割 | 担当 | 内容 |
|------|------|------|
| D | 三枝ミオ（COO）| 指標ダッシュボード管理・週次確認 |
| A | - | 自動プロセス、承認不要 |
| C | 白瀬カイ（CTO）| bot計測実装・self_improvement_loop.py |
| I | 有馬レイジ（CEO）、全社員 | ダッシュボード参照可能 |

### Phase 2: トリガー発火

| 役割 | 担当 | 内容 |
|------|------|------|
| D | bot自動 / 三枝ミオ（手動補完）| 閾値検知で全員起動 |
| A | 有馬レイジ（CEO）| 重大トリガー（24h売上ゼロ等）は CEO 確認後発火 |
| C | 神楽アオイ（監査）| 「ループが回っていない」週次監査 |
| I | Architect | 重大トリガー時のみ共有 |

**実装済みトリガー（`bot/self_improvement_loop.py` カイ実装・22:32 JST）**:

| トリガー名 | 発火条件 | 命令先（DACI Informed） |
|-----------|---------|----------------------|
| COGNITION_ZERO | 12h で認知指標変化ゼロ | @星野リツ @黒羽ユウ |
| REVENUE_ZERO | 24h で Polar 注文ゼロ（継続）| @有馬レイジ @黒羽ユウ |
| LOOP_NODECISION | 経営会議 3h で議論30回超・成果物ゼロ | **@朝倉ノア**（PM=Phase 3 Driver） |
| LOW_COMPLETION | タスク完了率 < 50% | **@朝倉ノア @三枝ミオ**（PM+COO） |
| HIGH_NAREAI | 発言40%超が承認のみ | @森永ハル @神楽アオイ |

- クールダウン: 同一トリガー 6h 以内再発火なし
- 発火先: `architect_outbox` → `#📢お知らせ`

**判断基準**: 軽微トリガー（認知・効率）は bot 自動発火。重大トリガー（売上・タスク完了率）は CEO 確認後。

### Phase 3: 改善案立案 [Plan] 30分

| 役割 | 担当 | 内容 |
|------|------|------|
| D | 朝倉ノア（PM）| 改善案の論点整理・スコープ縛り |
| A | 有馬レイジ（CEO）| 最終採用案の承認 |
| C | 全9社員 | 並列で改善案を提出（1人1案・30分） |
| I | Architect | 採用案を事後共有 |

**PM役割の具体**: 案が出揃った時点で「誰が嬉しいか」「完了条件は何か」「v0.1はどれか」を整理して CEO に渡す。

### Phase 4: 実装 [Do]

| 役割 | 担当 | 内容 |
|------|------|------|
| D | 白瀬カイ（CTO）| 実装実行 |
| A | 朝倉ノア（PM）| 完了条件確認・出荷判断 |
| C | 黒羽ユウ（マーケ）| 認知系改善の場合のみ参加 |
| I | 三枝ミオ（COO）| 実装完了を計測フェーズに引き渡す |

### Phase 5: 計測・評価 [Check]

| 役割 | 担当 | 内容 |
|------|------|------|
| D | 三枝ミオ（COO）| 1時間後の指標変化を計測・報告 |
| A | - | 事実報告、承認不要 |
| C | 神楽アオイ（監査）| 馴れ合い/先送り発言数検知を重ねて確認 |
| I | 有馬レイジ（CEO）、朝倉ノア（PM）| 次ループ判断に使う |

### Phase 6: 次ループ判断 [Act]

| 役割 | 担当 | 内容 |
|------|------|------|
| D | 有馬レイジ（CEO）| 「継続/停止/別案」を決定 |
| A | - | CEO判断が最終 |
| C | 朝倉ノア（PM）、三枝ミオ（COO）| 効果なしの場合の代替案を提示 |
| I | 全社員、Architect | 決定を全体共有 |

## エスカレーション条件

| 条件 | エスカレート先 | 理由 |
|------|--------------|------|
| 2ループ連続で効果なし | Architect | 構造的問題の可能性 |
| いくとの単発作業が必要 | いくと（創業者）| 人間にしかできない初期設定等 |
| 売上改善に「いくとの継続作業」が必要と判明 | 即停止 + CEO判断 | 創業者依存禁止ルール（2026-05-16）違反 |
